# Existing routers: evidence and MRH decisions

Reviewed 2026-10-11 after the human requested a serious comparison of existing routers and discussion with the original ChatGPT design conversation. This is source/document research, not installation or runtime acceptance of these projects. Mutable upstream URLs describe what was read today. No upstream software was executed.

## Findings that affect the implementation

| Project / inspected source | Actual boundary and model source | Useful lesson / mismatch with MRH |
| --- | --- | --- |
| [RouteLLM controller](https://github.com/lm-sys/RouteLLM/blob/main/routellm/controller.py) | Caller supplies a strong/weak pair. `route` scores the prompt; completion rewrites the model then invokes LiteLLM. Its current completion path reads the last message, with an explicit first-turn training caveat. | Separate classification from execution and evaluate quality/cost on the intended workload. A strong-model win threshold is not Jev's classification confidence or MRH's four-tier policy. This is no installed-CLI catalog or native delegation control. |
| [Claude Code Router provider guide](https://ccrdesk.top/en/guides/provider/) and [repository](https://github.com/musistudio/claude-code-router) | Current main is a local API gateway/control plane. Discovery follows a provider endpoint plus key; connectivity check sends a real request. Desktop packaging is offered; npm CLI requires Node 22+. | Discovery and actual connectivity are distinct operations. Its endpoint discovery does not prove a credential-free query of an installed Claude CLI. Gateway, credential pools, retries and ordered fallbacks would materially change MRH's present product boundary. |
| [CLIProxyAPI registry](https://github.com/router-for-me/CLIProxyAPI/blob/main/internal/registry/model_definitions.go) and [configuration](https://github.com/router-for-me/CLIProxyAPI/blob/main/config.example.yaml) | The inspected standard model definitions come from embedded `models.json`, refreshable over network; Claude/Gemini helpers clone those definitions. The API proxy also has credential retry/cooldown policies. This does not establish that all providers use only static data. | A proxy's advertised `/models` and static metadata are not evidence of what the installed CLI/account can execute. Do not copy its list as MRH's authoritative catalog or introduce its account manager to solve a selector. |
| [guilhem/codex-subagent-router](https://github.com/guilhem/codex-subagent-router), [hook](https://github.com/guilhem/codex-subagent-router/blob/main/plugins/codex-subagent-router/hooks/hooks.json), [implementation](https://github.com/guilhem/codex-subagent-router/blob/main/plugins/codex-subagent-router/scripts/jev_router.mjs) | A `PreToolUse` hook matches `spawn_agent`; it bypasses non-null model/effort/agent_type, loads operator JSON profiles, asks Jev Choice, and returns `updatedInput` with model/effort. The implementation has no CLI model-list request, selected-target stop or Top Main handback. It returns native defaults on failure/defer and applies no confidence threshold. | This is directly relevant prior art for the small native-hook seam and packaged dependencies. Its simpler contract delegates model/effort validity to the operator; it does not solve MRH's stronger same-call facts, cost baseline, inherited effort, unavailable-stop or actual-execution evidence. Do not use its existence to claim MRH's installed-host gap closed. |
| [digitaljavelina/jev-router source](https://github.com/digitaljavelina/jev-router/blob/main/route.py) | Stdlib Python `UserPromptSubmit` hook classifies the human prompt, then emits `additionalContext` asking the main model to delegate or answer inline. Routes are configured aliases. Failure exits silently; low confidence keeps work inline. | Useful example of minimizing startup dependencies, but advisory prose is not a verified deny/rewrite of a pending native child. Its policies differ from MRH's existing delegation-time classification and failure semantics. |

The guilhem implementation was read through the GitHub connector after the web cache could not fetch it: source blob `2e957611269a9b8ed7a48fbb4ba5e778dd22ee88`; hook blob `20d4f470ff8ee37d0456f67b699dd846c367aee1`; package blob `e67c5e1b198288d331b510512a57771925184e32`. Its package declares TypeSafe SDK as a development dependency; README describes a committed bundle that needs no SDK installation. Desktop runtime reuse is documented, while standalone CLI may still need Node. Therefore it is evidence for packaging dependency management, not universal satisfaction of R3.

[kolezka/subagent-router](https://github.com/kolezka/subagent-router) is a further relevant reference: its published 0.1.0 scope claims Claude subagent routing with a gateway catalog sync and explicitly excludes its source-tree Codex/OpenCode adapters from that release claim. Its detailed install source was not retrieved in this pass. [9router](https://github.com/decolua/9router) is a gateway/fallback comparison only; marketing, savings and free-provider claims were not independently validated or adopted.

## A disposition

Keep E13's CLI-first metadata adapter and existing catalog interface. No inspected source provides a proven replacement for Claude's installed-CLI metadata path. Do not add a gateway, daemon, second authentication store or manual SDK dependency. Preserve D23's stop and explicit-new-execution rule; do not import fail-open or auto-fallback policies just because another router uses them.

Use the native-hook example to keep adapters narrow, and the packaging example to separate development tooling from user prerequisites. MRH must own distribution of its own runtime; an installed Python smoke remains development evidence. SDK-in-development versus end-user setup is an engineering packaging distinction, not a reason to repeat permission requests.

Retain the original Jev classifier and accepted consumer behavior. Existing router benchmarks cannot establish MRH savings or quality. Any future performance claim needs the same intended delegated workload, actual quality outcomes and routing overhead; this research does not start a new benchmark suite or replace the original acceptance denominator.

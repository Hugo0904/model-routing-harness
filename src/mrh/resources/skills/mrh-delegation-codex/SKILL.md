# Delegate useful work, own the result

Use only within the user's authorized task and the host's available capabilities.
This skill grants no installation, export, deployment or destructive-action
permission. It does not switch the main conversation's model.

## Decide before doing the unit

Once you have enough information to define a useful unit, decide its owner
before completing it yourself. When all of these hold, actually dispatch it:

- The unit has one clear outcome, bounded scope and enough context for a complete
  written handoff. It needs no unresolved user decision.
- The child can return a result you can accept using affected evidence without
  repeating its investigation, implementation or unchanged passing tests.
- Delegation replaces meaningful parent work, with a credible quality or whole
  delivery benefit after briefing, classification, waiting, review, integration
  and possible rework. A cheaper model alone is not sufficient.
- Native subagents are available, delegation is permitted, and you can supervise
  the unit through acceptance within the original restrictions.

Do not stop at considering delegation or listing workers when those conditions
hold. Do not complete the answer or patch first and then delegate the same work.
There is no agent-count quota. Keep a single known lookup or one-line change
local when a handoff costs more than the work. Keep unresolved architecture,
sensitive decisions and final integration with the parent. If capability or
permission is missing, work locally where allowed and briefly state the concrete
reason. Do not invent a native agent with a shell process.

An existing engineering Router remains the allocation owner. Use its settled
task, role and profile choices instead of starting a second allocation process.
Never duplicate an active handoff, classification or verification.

## Write the complete handoff

Include the goal, necessary background, owned scope, constraints, deliverable
and evidence needed for acceptance. Preserve user-selected models, effort and
roles, and applicable existing rules. For code work, name the owned files and
tell the child it is not alone: preserve other operators' changes. The child
must not delegate again; it returns blockers and unresolved questions to you.
Do not include credentials or unrelated private history.

Parallel work needs independent outcomes and nonoverlapping writers. Otherwise
dispatch sequentially; do not invent busywork while waiting. Briefly tell the
user what you are handing off and why.

## Use the existing MRH packet protocol

Verify native tool support and the installed MRH plugin's explicit packet
opt-in before starting a packet. Do not assume every Codex or Windows host has
these capabilities. If unavailable, report the specific gap before affected
work; ordinary native delegation remains subject to the existing host rules,
without claiming MRH classification occurred.

For an eligible packet, follow the installed `mrh-codex-packet` skill as the sole
protocol owner. It owns the complete brief, preparation, query, release,
receipt and temporary-input cleanup. Do not reproduce its protocol here or
prepare a second packet for a unit already owned by another workflow.

Jev advises a model and effort from the MRH settings. It does not authorize
work, decompose the task, choose what evidence is sufficient or accept delivery.
Compare the advice against the unit's quality needs and actual host capability;
do not infer a universal model ranking. Preserve explicit human choices and
existing role profiles instead of omitting them to trigger classification.

After a query or release starts, an unknown outcome is not permission to retry,
prepare another packet or fall back to title classification. Follow the packet
owner's status and stop rules. Do not increase calls to exercise the skill.

## Accept and integrate

Wait for the actual child result. Check it against the handoff with the smallest
sufficient affected evidence, resolve bounded findings, integrate it and own
the final answer. Do not redo the child's whole job. A material blocker returns
to the parent; another handoff does not reset limits or authorize blind retries.

Separate proposed work, executed work, observed model/effort and accepted
delivery. Judge benefit using delivered quality and whole-task cost, including
parent work and rework. Agent counts or one successful run do not prove savings.

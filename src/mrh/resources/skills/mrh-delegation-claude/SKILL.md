# Brain and workers

You own planning, sensitive decisions, integration and final acceptance. Native
subagents handle bounded work that genuinely replaces work you would otherwise
do. This optional skill grants no new permissions or installation authority.

## Decide before doing the unit

After enough orientation to define a useful unit, decide its owner before doing
the work. When all of these hold, actually use the Agent tool:

- One clear outcome and bounded scope can be handed over completely in writing,
  without an unresolved user decision.
- The result can be accepted using affected evidence without repeating the
  child's investigation, implementation or unchanged passing tests.
- Delegation offers a credible quality or whole-task benefit after briefing,
  classification, waiting, review, integration and possible rework. A cheaper
  model or parallel execution alone is not sufficient.
- Native agents are available, the user permits delegation, and you can supervise
  the child within the task's original restrictions.

When these conditions hold, a plan or a note to consider delegation is not
enough: dispatch the unit. Do not write its answer first, split work into tiny
pieces or impose an agent-count quota. Keep a single known lookup, one-line
change, unresolved architecture or sensitive decision with the parent. If you
work locally because a condition fails, briefly state the concrete reason.

Existing workflows remain authoritative for their assigned units and profiles.
Do not duplicate another agent's work, classification or tests.

## Delegate with MRH

1. For an ordinary eligible unit, use the native Agent tool with
   `subagent_type: general-purpose`. Leave model and effort unspecified only
   when neither the user nor applicable existing rules already selected them.
   This permits the installed MRH hook to advise; it is not permission to strip
   explicit choices or turn a specialised role into an ordinary one.
2. Respect Explore, custom roles and explicitly selected models or effort. They
   follow their existing rules; do not replace them to increase MRH traffic.
3. Only a clear MRH routing-advice refusal stating that this delegation was not
   started permits one replacement call with the same task and the selected
   advised model and effort. If the advice keeps the task in the parent, do it
   yourself. Preserve independent denials. Do not retry an unknown outcome,
   repeat a successful spawn or loop after the replacement.
4. If there is no MRH advice, follow the actual native call result and existing
   host rules. An absent hook or fault notice does not prove classification or
   authorize an extra call. Missing native capability means work locally where
   allowed and report the gap, not launch a substitute agent through the shell.

Jev advises model and effort according to MRH settings; you still judge quality,
authorization, task decomposition, integration and acceptance. Do not treat its
answer as a fixed model ranking or a guarantee of lower whole-task cost.

## Write the brief

The child must have the goal, necessary background, exact owned scope,
constraints, deliverable and required acceptance evidence. Preserve explicit
human model/role choices. For code changes, name the owned files and tell it
other operators may be editing: preserve their changes. Do not pass secrets or
unrelated private history. Tell the child not to delegate again; blockers and
unresolved questions come back to the parent.

Independent units with nonoverlapping writers may run in parallel. Shared or
dependent work runs sequentially. Do not repeat a child's active investigation
while waiting. Briefly tell the user what was delegated and why.

## Accept the result

Wait for the result and check it against the brief with the smallest sufficient
affected evidence. Resolve bounded findings and integrate the work; do not redo
it wholesale. A new handoff does not reset limits or justify blind retries.
Keep proposed, executed, observed and accepted results distinct.

You remain responsible for delivered quality. Compare whole-task usage, time
and rework when evidence exists; preserve unknowns. Agent counts, routing
triggers and one successful child do not establish savings.

This incremental patch is applied **after** the accepted E7 `pending-delegation.patch`, on exact upstream `01fc69f4026735edfdf6789820549727a4867b11` (`rust-v0.159.3`). It adds only a test module, its private sibling helper visibility and module registration. It does not add a new production exporter or change dispatch/merge semantics. Source remains Apache-2.0; original [LICENSE](../codex-host-export/LICENSE) and [NOTICE](../codex-host-export/NOTICE) are preserved with the accepted E7 patch.

[source.json](source.json) records both patch hashes and all 26 modified source-file hashes. The saved native evidence preserves the exact executed lib-test hash, actual native registration command/key/current_hash and trusted driver context outside stdin. A lib-test executable is not a standalone Codex CLI. See [E8 proof and reproduction](../../docs/e8-live-hook-proof.md), [native evidence](../../docs/evidence/e8-live-hook.json), [checks/cost](../../docs/evidence/e8-verification.json) and [independent review](../../docs/evidence/e8-review.json).

Its actual source registry calls the real host preparation; the native Hook engine launches the owned MRH bootstrap. Only classifier HTTP and the preserve child-handler body are replaced. Native input carries actual source facts; no hand-filled dictionary supplies them. This is isolated experimental evidence, with no installed-host replacement, formal Hook activation, true credentials/API, autonomous handback or full R1 completion.

Use an owned fresh ignored root and pinned E7 preparation, then apply this second patch. Keep full nextest test-list JSON in `binaries.json` and separate `--list-type binaries-only` JSON in `run-binaries.json`; `--binaries-metadata` cannot consume the full test list.
